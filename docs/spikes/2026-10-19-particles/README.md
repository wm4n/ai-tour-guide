# 語助詞安全清單實測（2026-10-19）

回答設計文件 6.4 節的待辦：哪些語助詞與口語句型會讓 KittenTTS 2 合成失敗。對應 issue #16。

## 方法

- 12 個候選詞，每個詞 3 個自然的口語句 × 3 個 seed（1234、7、42），共 108 次合成
- 合成與驗收走 `host/` 的語音管線：KittenTTS 2 + F2 參考聲音 → Whisper small 轉寫 → CER（數字、繁簡先統一）
- 過關門檻：CER ≤ 0.20（與管線預設相同）
- 判定：9 次全過＝safe；過關率 ≥ 75%＝caution；其餘＝unsafe
- 測試句在 `host/src/buddy_host/speech/particles.py`，原始資料在 [`particles.jsonl`](particles.jsonl)
- 重現：`cd host && uv run python -m buddy_host.speech.particle_probe`（需要 `uv sync --group speech` 與參考聲音）

## 發現

1. **失敗幾乎都出現在句首的感嘆詞**：「哇，」「欸，」的失敗率最高（6/9、7/9），Whisper 的轉寫常常多出一段亂碼前綴（例如「欸，你有沒有聞到一股茶香？」被轉成「我叫孟子英國，英國，茶香。」）。「欸」有一句三個 seed 全敗。
2. **其餘詞多半只是單一 seed 失敗**，管線換 seed 重試即可兜底：對了、而且、其實、你看、喔、吧、啦、一下下，整段被跳過的機率 ≤ 0.2%。
3. 失敗時常見的模式是**開頭多出一段不存在的音節**（「吧」的失敗樣本：「有無萬盈興，我們先往前走走看吧。」），不一定和那個語助詞有關，而是這類短句整體較不穩。
4. 「啊」九次全過，是這批 CER 最漂亮的詞。
5. 名花之里原稿開頭的「哇！」在併成一段後通過驗收（#4 實測），所以句首感嘆詞的風險與**單獨成句**有關；但上表的失敗句是「哇，」直接接在句首，仍然不穩。

## 限制（重要）

**CER 只量得出「聽不聽得懂」，量不出「像不像粵語腔」。** 設計文件 6.4 節把「欸、啊、喔、吧、一下下」列為避免，依據是使用者試聽的主觀感受（口音跑成類粵語腔），這批資料既不能證實也不能推翻。因此「啊」雖然 CER 全過，也**不改判為安全**，要等人耳確認。

`--listen` 選項會把每個詞的第一句（seed 1234）存成音檔，供人耳確認：

```bash
uv run python -m buddy_host.speech.particle_probe --listen ~/.buddy-host/out/particles-listen
```

## 結論（寫進 `host/config/buddy.md`）

| 類別 | 詞 | 理由 |
|---|---|---|
| 避免（聽感） | 欸、啊、喔、吧、一下下 | 使用者試聽時聽到類粵語腔；CER 無法推翻，待人耳確認 |
| 避免（驗收失敗率高） | 哇、欸、呢 | CER 實測：句首感嘆詞與句尾「呢」失敗率高 |
| 可以用 | 對了、而且、其實、你看、啦 | CER 過關，失敗只偶發在單一 seed，重試可兜底 |

親切感改靠句型和用詞營造（「我們」「你看這裡」「對了，」「其實」）。
