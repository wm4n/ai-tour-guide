# 從 App 切換旅伴聲音 設計

- 日期：2026-10-21（2026-10-22 grill 定案）
- 前置：#28（每個聲音的 `voice.toml`：語速與回答停頓，PR #29 已合併）
- 狀態：已定案（grill 完成）

## 為什麼

主機上已經有多個可用的參考聲音（目前四個：兩女兩男，都設定 `speed = 1.2`、`answer_max_pause_seconds = 0.45`），但換聲音只能改主機的 `~/.buddy-host/config.toml` 再重啟。使用者想要的情境是**走在路上突然想換一個聲音**（聽膩了、想換口味），所以要能在 App 的旅程畫面上直接換，換了之後接下來聽到的都是新聲音。

成功的樣子：旅途中打開設定、點一個聲音，正在講的這段講完，之後的介紹、回答、固定短句全部變成新聲音；不用碰主機、不用重新 build App。

## 目標

1. App 的設定頁可以看到主機上所有聲音、試聽、點一下就切換。
2. 切換時：
   - **正在播的那一段用舊聲音播完**（不中途切斷）。
   - **還沒播的舊聲音介紹全部丟掉**，以新聲音重做；使用者接受重做期間（M3 上約數分鐘）比較安靜、可能錯過一兩個景點。
   - 之後的主動介紹、回答、固定短句都是新聲音。
3. 固定短句（App 在連不上主機時也要能播）跟著聲音換：由主機為每個聲音自動合成、自動挑驗收最好的一版，App 下載存在手機裡。
4. 主機重啟後記得最後選的聲音。

## 不做（non-goals）

- 調整語速、停頓等聲音參數的 UI（仍在主機的 `voice.toml`）。
- 從 App 新增／刪除聲音（新增聲音仍是在主機放參考錄音）。
- 整個 App 的視覺改版（另案）。
- 字音（聲調）錯誤的修正（另案）。
- 人工挑選短句的舊流程（`out/phrases/`、`--finalize`、`phrases-final/`、`install-phrases.sh`）改成認得聲音。
- 更新 App 內建的 `assets/phrases/`。
- 清除手機裡舊聲音的短句檔。

## 絕對不要（anti-goals）

- repo 裡出現說話者真名、節目名或參考錄音／逐字稿（repo 是公開的）。聲音在 repo 裡只用中性代號（例如 `F2`、`M1`）；顯示名稱與描述只存在主機的 `voice.toml`。
- 換聲音後還聽到舊聲音的**介紹**（正在播的那段除外）。
- 換到一個固定短句還沒準備好的聲音，結果連不上主機時無聲或播出別的聲音的短句。
- 換聲音造成 Claude 重新寫稿（舊稿可直接用新聲音重新合成，見 #28 的快取）。
- 換聲音造成已經講過的景點（已播完、被打斷）用新聲音再講一次。

## 使用者決定的部分

| 項目 | 決定 |
|---|---|
| 什麼時候換 | 走在路上隨時換 |
| 換的當下 | 正在播的播完；未播的舊聲音介紹丟掉重做；之後全是新聲音 |
| 介面位置 | 旅程畫面右上角的齒輪改成完整「設定」頁，聲音與主機設定放同一頁（草圖選項 C） |
| 試聽、描述 | 要：每個聲音可試聽一句、顯示簡短描述（例如「女聲・溫暖」） |
| 固定短句 | 主機自動合成、自動挑驗收分數最好的版本，不必人工挑 |
| 哪些算聲音 | 只有放了 `voice.toml` 的資料夾才是正式聲音、列在 App 上；其餘資料夾（篩選時留下的候選）不列出 |
| 下方標「判斷」的項目 | 2026-10-21 使用者逐項確認同意 |
| 標「grill」的項目 | 2026-10-22 grill 時使用者確認（Q1–Q16） |

## 設計（我的判斷標註為「判斷」，grill 定案標註為「grill Qn」）

### 主機

1. **聲音清單與描述**
   - **只有 `voice.toml` 存在的資料夾才列為聲音**（使用者決定）。`voice.toml` 對「能不能被主機拿來合成」仍是選填（沒有的照舊原速），但要出現在 App 清單上就必須有。新增聲音的步驟：放 `ref_24k.wav`、`ref_text.txt`，寫 `voice.toml`（至少 `display_name`），再產生固定短句（見第 4 點）。
   - `voice.toml` 新增選填欄位 `display_name`（App 上顯示的名稱，預設為資料夾名）與 `description`（例如「女聲・溫暖」）。（判斷）
   - `GET /v1/voices`：回傳每個聲音的 `name`（資料夾名，切換用）、`display_name`、`description`、`phrases_ready`（目前語速的固定短句是否都已合成）、以及目前使用中的 `current`。**每次請求都重讀硬碟**，所以改了 `voice.toml` 的名稱、描述、語速不必重啟就反映在清單上。（grill Q8）
2. **切換**
   - `POST /v1/voice`（`{"name": …, "playing_id": …, "played_ids": […]}`）：聲音不存在回 404；固定短句沒準備好回 409（App 不讓選，見下方）。切到目前已在使用的聲音直接回 200，不做任何事。
     - `playing_id`：App 當下正在播的介紹（沒有就省略），主機把它當成「會播完」，不丟掉重做。（判斷）
     - `played_ids`：App 還沒送達主機的「已播完」回報（`_unreportedPlayed`），加上被問題打斷、等著接續的那段。主機**在丟棄之前**先把它們記成講過（同 `/v1/tour/played`），避免它們被當成未播而用新聲音重講。（grill Q6）
   - **切換延後生效、請求立刻回應**：主機記下新聲音後立即回 200（含新的 `current`），實際換合成器、丟未播介紹、重新準備都在背景進行，避免超過 App 的 10 秒逾時。（判斷）
   - **連續切換以最後一次為準**：背景切換還沒做完又收到新的切換，就放棄前一個的重做、改做最新的；不回 409。（grill Q2）
   - 目前使用中的聲音存在主機本機 `~/.buddy-host/voice/current`（一行資料夾名，原子寫入），重啟時優先於 `config.toml` 的 `voice`；檔案不存在才用 `config.toml`。（判斷：不改寫含 token 的 `config.toml`）
   - 切換時**重讀該聲音的 `voice.toml`**（語速與 `answer_max_pause_seconds` 都跟著換）。正在使用中的聲音改了 `voice.toml`，要重啟或「切走再切回」才套用到合成。（grill Q8）
   - 合成器在**合成單位之間**換聲音：正在合成的單位（介紹的一段或答案的一段）用舊聲音做完，下一個單位起用新聲音。正在進行的**回答**整個用舊聲音講完，下一題才換。（判斷）
     - 換聲音不必重載 KittenTTS 模型：參考音檔與逐字稿本來就是每次 `generate()` 傳入，speaker embedding 由函式庫依參考自動快取；要改的是合成器持有的 `_voice` 可替換。
     - `install_speed` 目前只能裝一次、不能還原（`speed == 1.0` 時直接返回，留下舊的加速 decode）；要改成可以依新聲音的 `speed` 重設，切回 1.0 時移除實例上的 `decode`、恢復函式庫原本的方法。
     - `answer_max_pause_seconds` 目前在啟動時寫死在 `PipelineConfig`；要改成跟著目前聲音。
   - 主機啟動時若目前聲音的固定短句沒準備好：日誌大聲警告，照常運作；App 依 `phrases_ready` 顯示警示。（grill Q4）
   - 沒有在旅程中時切換：只換聲音，沒有介紹要丟。
3. **丟掉未播的舊介紹並重做**
   - 每段介紹的事件（`/v1/tour/narrations` 回應的每一筆）加上 `voice`（聲音鍵，如 `M1@1.2`）；回應本身也帶目前的 `voice`。
   - 切換時，主機先處理 `played_ids`，再把「已發布但 App 還沒回報播完」的介紹從已發布清單（`_published`、`_audio`）**與事件清單（`_events`）**移除，並**先於下一次準備**把這幾段的稿子用新聲音重新合成後再發布（不重新排序、不呼叫 Claude）。已回報播完的、以及 `playing_id` 那一段不動。（grill Q11）
     - 實作時改掉原本「以最後一次位置重新準備」：快取的指紋含「這趟剛講過什麼」，切換前若剛播完一段，重新準備時指紋就對不上，Claude 會重寫稿。撤下的景點這趟維持排除（重做失敗也一樣），不會被重新排序後重寫。（#35 實作）
   - **不浪費已寫好的稿子**：進行中的準備不中斷；每一段都用做好當下的聲音合成，所以切換時正在寫的稿子寫完後直接用新聲音合成。稿子在合成之前先存進快取。合成途中換過聲音（含換走又換回）的那一版丟掉，用最新的聲音重做。換聲音絕不造成重寫稿或多耗 `--max-llm-calls` 的次數。（判斷；#35 實作）
   - 介紹準備器的聲音鍵改為可變（目前在建構時固定）；快取的稿子照 #28 的方式用新聲音重新合成，不呼叫 Claude。
   - **快取依聲音分開**（grill Q9）：
     - 稿子與指紋（`narrations/<景點>.meta.json`）每個景點一份，與聲音無關。
     - 音檔改放 `narrations/<聲音鍵>/<景點>.wav`（`.log.json` 同處），切回之前用過的聲音時直接命中，不必再合成。
     - 現有平放的 `narrations/<景點>.wav` 不再使用；下次用到該景點時從稿子以目前聲音重新合成（不呼叫 Claude）。
   - 重做的介紹沿用同一個景點 id，以新的 seq 發布。
4. **固定短句**
   - 每個聲音的短句放在 `~/.buddy-host/out/voice-phrases/<聲音鍵>/<編號>.wav`，聲音鍵含語速（例如 `F2@1.2`）：改了 `voice.toml` 的語速，那個聲音就變成「短句未準備」，要重新產生。和人工挑選流程的 `out/phrases/<編號>/` 分開，舊流程原封不動。（判斷；路徑 grill Q13）
   - 產生方式：`python -m buddy_host.speech.phrases --voice <聲音> --auto`（判斷：不在主機服務裡背景自動合成，避免和介紹／問答搶 GPU；新增聲音時在主機手動跑一次）：
     - 每句最多試 8 個 seed（`--max-seeds` 可調），在**通過現有門檻**（句首檢查；20 字以內 CER ≤ 0.05，其餘 ≤ 0.20）的版本裡挑 CER 最低（同分取較短）的一版寫入上述路徑。
     - 某句沒有任何版本通過：不寫入那一句，該聲音維持「短句未準備」；CLI 列出失敗的句子並以非 0 結束，可加大 `--max-seeds` 再跑。（grill Q7）
   - **四個聲音（含 F2）上線前都用 `--auto` 在 M3 上產生一次。** F2 現有那批人工挑選的短句是原速合成的，和 1.2 倍的介紹語速不一致，不沿用（使用者選了自動挑選）。M6 到貨後，在 M6 安裝步驟中為每個聲音重新跑 `--auto`（在當地重新驗收），不從 M3 複製。（判斷；M6 grill Q15）
   - `phrases_ready` 依主機的 `PHRASES`（1、2、3、4、6、7）判斷每一句的檔案都存在。（grill Q10）
   - `GET /v1/voices/{name}/phrases/{number}`：下載某個聲音（目前語速）的某句短句；不存在回 404。
   - 試聽：播放該聲音的 7 號短句（「好，我們出發吧！」）。（判斷）
5. 所有新端點同樣需要 `X-Buddy-Token`。

### App

1. **設定頁**（取代目前的 `SettingsDialog`）
   - 旅程畫面右上角的齒輪開啟完整設定頁（push 一個頁面；旅程 controller 是全域的，設定頁開著時旅程照常進行），分兩區：「聲音」與「家裡的主機」（網址、token，原本的欄位）。
   - 聲音區列出 `GET /v1/voices` 的結果：頭像（顯示名稱首字）、顯示名稱、描述、試聽按鈕（▶）、使用中打勾。`phrases_ready` 為否的聲音顯示為不可選並註明「短句尚未準備」；若是**目前使用中的聲音**短句未準備，顯示警示。（grill Q4）
   - 點選聲音即切換（不需「儲存」）。切換中顯示進度；完成後回到旅程畫面時，看得到「這段播完就換，下一段準備中…」的提示。
   - 連不上主機時，聲音區顯示目前使用的聲音但不能切換。
   - **試聽**：直接從主機串流 7 號短句，不存進手機。試聽時把正在播的介紹當成「被發問打斷」處理（沿用 `_interruptNarration`／接續機制），試聽完從那一句開頭接著播。（grill Q5）
2. **切換流程**
   1. 使用者一點新聲音，**立刻停住介紹佇列**：正在播的那段播完，但不再開始任何舊聲音的介紹，直到切換成功或失敗；失敗就恢復佇列。（grill Q1：避免下載／等回應的空檔裡又開播下一段舊介紹，之後被重講）
   2. 下載新聲音的全部固定短句（依 App 的 `FixedPhrase` enum）存到手機（App 的文件目錄，依聲音鍵分資料夾）；任何一句失敗就不切換、提示錯誤。（grill Q10）
   3. 呼叫 `POST /v1/voice`，帶上正在播的介紹 id（`playing_id`），以及 `played_ids`（尚未送達的已播完回報＋被打斷、等著接續的那段）。成功後把這些從 `_unreportedPlayed` 清掉。（grill Q6）
   4. 成功後：App 記住目前聲音；佇列中聲音不是新聲音的介紹全部丟掉（**正在播的那段例外**，讓它播完），並把**丟掉的那些 id 從 `_seen` 移除**，讓同一景點的重做版能再進佇列。（grill Q11）
   5. 被問題打斷、等著接續的那段介紹：不接續、不用新聲音重講（已在第 3 步以 `played_ids` 記成講過）。（判斷：避免同一段聽兩次）
   - 去重維持只看 id（不用 id＋聲音鍵：A→B→A 時同一景點的 A 版重做會被當成看過而擋掉）。（grill Q11）
   - 連續切換以最後一次為準：切換中仍可再點別的聲音。（grill Q2）
3. **目前聲音以主機為準**（grill Q3、Q12）
   - App 記住的目前聲音只用在離線時挑短句。
   - 旅程中：`/v1/tour/narrations` 回應帶的 `voice` 和 App 記的不同，就改成主機的，沒有該聲音的短句就自動下載。
   - 不在旅程中：打開設定頁、或連線從斷到通時，呼叫 `GET /v1/voices` 同步。
4. **固定短句播放**
   - 改為優先播放手機裡「目前聲音」的短句檔；手機裡沒有時退回 App 內建的 `assets/phrases/`（只剩「從沒連上過主機」會用到；內建檔不更新，grill Q14）。
   - App 連上主機時（含第一次），若手機裡沒有目前聲音的短句就自動下載，所以平常不會退回內建的舊短句。（判斷）
   - 切換當下若有回答正在進行，那個回答用舊聲音講完，但 App 端的提示短句（3、4 號）已是新聲音；接受這個小落差。
5. **輪詢**：`/v1/tour/narrations` 收到的介紹，若 `voice` 和目前聲音不同就不加入佇列（處理切換前已在途的回應）。

## 限制

- M3 上新聲音重做一段介紹約數分鐘；切換後到第一段新聲音介紹之間會比較安靜。M6 會快一些。
- 換聲音後，回答問題的第一段延遲不變（換聲音不增加負擔）；但若正在合成介紹的一個單位，切換要等那個單位做完。
- 主機一次只有一個聲音（只有一顆 GPU、一個合成器）。
- 短句清單在主機 `PHRASES`、App `FixedPhrase` 各一份，靠各自的測試鎖成 1、2、3、4、6、7，不另做同步。（grill Q10）

## 驗收（grill Q16）

自動測試：主機 pytest（假合成器）、App widget／controller 測試（fakes），照現有慣例。

實機驗收（iPhone＋家中主機，使用者走路實測）：

1. 旅程中、介紹播到一半時切換：這段用舊聲音播完；之後聽不到舊聲音的介紹；下一段是新聲音。
2. 試聽會打斷正在播的介紹，試聽完從那一句開頭接著播。
3. 切換後關掉主機：「連不上主機」的短句是新聲音。
4. 重啟主機：仍是最後選的聲音，App 顯示正確。
5. 被打斷的那段不會用新聲音再講一次；`usage.jsonl` 在切換前後沒有多出寫稿呼叫。
6. 「短句未準備」的聲音不能選。
